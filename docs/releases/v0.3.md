# V0.3 — Explicit pipeline IR and generic resource scheduler

V0.3 introduces a typed pipeline intermediate representation and a
deterministic list scheduler whose decisions are driven exclusively by edges,
resource demands, capacities, and loop semantics. It does not classify work by
operator, node, or hardware-stage names.

The IR includes resource, work, buffer/access, node, edge, loop, launch, and
compact schedule records. Validation rejects missing references, dependency
cycles, invalid work units, impossible resource demands, invalid queue
capacities, and undersized buffer rings. Loop-carried dependencies and resource
calendars are operational, and compact schedules reconstruct bounded trace
windows with `trace_window()`.

Matmul now emits this IR for each selected kernel candidate. During the V0.3
transition the result retains the established detailed timeline and includes
the generic IR schedule plus a machine-readable legacy comparison report. The
two cycle totals are not expected to match: the established model charges
phase-specific latency hiding and epilogue work, while the first generic graph
uses steady-state work durations and currently covers the recurring K loop.
This difference is labeled `expected_model_semantics_change`; it is not an
accuracy claim.

Known limitations:

- Queue capacity is a deterministic in-flight reservation limit, not an
  instruction queue simulation.
- Buffer validation follows declared producer/consumer edges; implicit data
  hazards are outside the schema contract.
- Matmul epilogue and chip-level CTA wave expansion remain in the established
  compatibility timeline. V0.4 will express them as explicit resources and
  launch policy.
