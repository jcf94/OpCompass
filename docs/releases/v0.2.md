# OpCompass v0.2 Release Notes

OpCompass v0.2 is a contract-and-correctness release. It makes the current
matmul-first analytical model explicit and reproducible; it does not claim to
be a general or measurement-calibrated GPU performance predictor.

## Highlights

- Concrete workloads are validated and canonicalized through explicit
  per-operator parameter specifications.
- Results distinguish requested and executed modes. Permissive fallback is
  visible and strict mode rejects unsupported analysis.
- Results identify estimate kind, support level, model, schema, implementation
  revision, hardware-spec version, evidence, and uncertainty status.
- Pipeline JSON is compact by default. Trace expansion is opt-in and capped at
  5,000 sub-operations.
- `/api/analyze` has closed Pydantic request, response, and error contracts,
  backed by real ASGI HTTP tests.
- CLI JSON and CSV serialization reject non-finite output and use stable,
  standards-compliant schemas.
- First-party and optional SOLAR tests are separately selectable.
- Wheel and sdist builds include the Web UI and SOLAR architecture resources;
  a clean-install smoke script verifies both distribution formats.
- The Web UI displays fallback, executed mode, model identity, evidence, and
  uncertainty.

## Compatibility impact

Consumers should migrate from the legacy `mode` field to `requested_mode` and
`executed_mode`. `mode` remains as a deprecated compatibility alias throughout
the 0.2 line. Pipeline traces are no longer returned unless `include_trace` is
true. Errors from `/api/analyze` use `{"detail": {"code": ...}}` instead of a
mixture of plain strings and objects.

The semantic result schema is `0.2.0`; package build versions such as
`0.2.0.dev0` are tracked separately. See
[Schema compatibility](../reference/schema_compatibility.md) for the policy.

## Verification

The release-candidate baseline is:

```text
pytest -q                       160 passed
python scripts/package_smoke.py passed
node --check web/js/app.js      passed
```

The supported-Python CI matrix is intentionally not part of this release. The
current release baseline was verified locally on Python 3.8; the packaging
metadata continues to declare `>=3.8` for source compatibility.

## Known limitations

See [Known limitations](../reference/known_limitations.md). In particular,
`hierarchy_roofline` is not yet a true hierarchy model, detailed pipeline
analysis is Matmul-only, and uncertainty is not measurement-quantified.
