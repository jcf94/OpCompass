# V0.4 — Memory paths, synchronization, and launch semantics

V0.4 extends the explicit pipeline IR with typed HBM, L2, copy, shared-memory,
register, TMEM, compute, synchronization, and store resources. Memory work now
declares its path, byte and transaction counts, transaction granularity, and a
first-order reuse policy.

Matmul graphs use architecture-specific synchronization sequences:

- Ampere: cp.async commit/wait and syncthreads;
- Hopper: mbarrier and WGMMA commit/wait;
- Blackwell: mbarrier and UMMA commit/wait.

Launch policy records compute-unit and resident-block capacity, wave count,
small-grid underfill, tail-tile utilization, and optional launch overhead.
These values are explicit model inputs or outputs rather than hidden scheduler
heuristics.

Current scope remains analytical. Transaction counts and CTA-order reuse are
first-order descriptors, not cache simulation; non-published instruction
latencies remain model assumptions until measurement overlays are introduced.
